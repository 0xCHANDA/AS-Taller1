# ADR 6 — Separar la creación de vacunas

## ADR-006: Crear `FabricadorVacunas`

### Contexto

Antes `Hacienda` tenía toda la lógica para crear vacunas.

Tenía cuatro sobrecargas de `crear_vacuna()`:

```csharp
crear_vacuna(... periodo_aplicacion ...)
crear_vacuna(... grado_atenuacion ...)
crear_vacuna(... periodo_aplicacion, cantidad ...)
crear_vacuna(... grado_atenuacion, cantidad ...)
```

Esto hacía que `Hacienda` tuviera que encargarse de:

- Crear vacunas bacterianas.
- Crear vacunas vivas.
- Crear lotes de vacunas.
- Validar nombre.
- Validar lote.
- Validar fechas.
- Revisar duplicados.

Además de todo lo demás que ya hace `Hacienda`, como manejar potreros, reses, ventas y vacunación.

### Alternativa 1

Mantener toda la creación de vacunas dentro de `Hacienda`.

Se descarta porque `Hacienda` seguiría teniendo demasiadas responsabilidades y cualquier cambio en las reglas de creación de vacunas obligaría a modificarla.

### Alternativa 2

Crear una clase específica:

```csharp
FabricadorVacunas
```

encargada solamente de crear y agregar vacunas.

Por ejemplo:

```csharp
fabricadorVacunas.Crear(...);

fabricadorVacunas.CrearLote(...);
```

De esta manera `Hacienda` solamente coordina y delega la creación.

### Decisión

Elegimos crear `FabricadorVacunas`.

Ahora `Hacienda` delega la creación de vacunas:

```csharp
return fabricadorVacunas.Crear(...);
```

o:

```csharp
return fabricadorVacunas.CrearLote(...);
```

Así la lógica de creación y validación queda concentrada en una clase específica.

### ¿Qué ganamos?

- `Hacienda` tiene menos responsabilidades.
- Se elimina gran parte de la lógica repetida de creación de vacunas.
- Las validaciones de creación quedan en un solo lugar.
- Si cambian las reglas para crear vacunas, el cambio se concentra en `FabricadorVacunas`.
- `Hacienda` queda más enfocada en coordinar las operaciones del sistema.

### Consecuencia negativa

`FabricadorVacunas` sigue conociendo directamente a `Bacteriana` y `Viva`.

Si en el futuro aparece un nuevo tipo de vacuna, por ejemplo:

```text
Toxoide
```

sería necesario modificar `FabricadorVacunas`.

Aceptamos esto porque actualmente solo existen dos tipos de vacuna y crear una interfaz o una jerarquía más compleja aumentaría la complejidad sin una necesidad real.

- **SRP**
- **OCP**
